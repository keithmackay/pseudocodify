# plsfix review: instruction documents (2026-11-17)

**Scope:** `CLAUDE.md`, `CONTRIBUTING.md`, `docs/TESTING_GUIDELINES.md`, each rewritten in place. All rules are kept with their meaning.

**Method:** Each document was checked against all 12 plsfix principles in order: Structure (P1–P4), Content (P5–P8), Delivery (P9–P12). Principles are cited by number and by the name `SKILL.md` uses: **P4: Use structural markup**, **P5: Be specific**, **P9: Say what to do**. Principles that `SKILL.md` doesn't name are cited by the name in the skill's principle table. Under each report, "Principles Not Triggered" lists every principle that needed no change, with the reason.

## Note on docs/TESTING_GUIDELINES.md

This file describes a different project. It is titled "HabitPeeps Testing Guidelines" and covers a Flutter/Dart app: `flutter test`, Playwright against `localhost:8080`, habits, peeps and streaks. pseudocodify is a Python CLI tested with `pytest`, and nothing else in the repo links to the file. plsfix doesn't invent scope, so the file was tightened as written and **not** retargeted to pseudocodify. Keith needs to decide whether to delete it, replace it with pseudocodify guidance, or keep it on purpose.

**Principles Not Triggered:**
- **P1: Context first, ask last.** The role and Rule #1 come first, then grouped rules. It is a rule set, so there is no single request to bury.

- **P7: Define the output contract.** The outputs it governs have stated formats: the commit message format (phase and task number, with an example) and the 2-line `ABOUTME:` file header.

- **P10: Make the stakes real.** Key rules give reasons: honesty ("you'll be replaced"), test failures ("Broken Windows theory"), output ("logs… contain CRITICAL information"), sycophancy.
- **P11: Give an out for uncertainty.** "STOP and ask for clarification", "STOP and ask for help", "Strange things are afoot at the Circle K" and "Say 'I don't understand X'" all cover uncertainty.

Also checked for P12, and consistent: "remove old comments" when refactoring vs. "NEVER remove code comments unless you can PROVE they are actively false". After a refactor, comments that describe the old code are false, so both rules apply together.

### Ambiguities reported, not changed

The repo has no evidence to settle these, so the original wording is kept:

- **Coverage metric not named (P5).** "Test Coverage Requirements" gives 100% / ≥90% / ≥80% thresholds without saying whether they mean line or branch coverage, while the pyramid section uses line coverage for unit tests and branch coverage for widget tests. There's no Flutter coverage config here to check.
- **E2E path mismatch (P5).** "Running Tests" runs `npx playwright test e2e/habit_creation_flow_test.ts`, but "Directory Structure" puts E2E tests in `test/e2e/`. The two agree if Playwright's `testDir` is `test/`, but there's no Playwright config here to check.
